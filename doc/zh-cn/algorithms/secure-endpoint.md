# 什么算是可以发送密钥的安全去处

*由里程碑 M6 交付。一个纯函数，每个判定都带具名的理由，因此界面能自我解释，整张表也能在没有网络的情况下被
测试。*

问题很窄：本应用可以把一个 API Key 复制到用户配置的 WebDAV 服务器上吗？答案必须保守，因为判断错了就意味着
把一份凭据以明文送上公开互联网。

## 允许

**任何 HTTPS。** 传输是加密的，问题到此为止，主机是谁并不重要。

**到流量出不去的地方的明文 HTTP。** 具体是：回环；私有 IPv4 段；链路本地；Tailscale 分配的运营商级 NAT
段；IPv6 的回环、链路本地与唯一本地地址，后者涵盖 Tailscale 自己的范围；以 `.ts.net`（Tailscale）或
`.et.net`（ZeroTier）结尾的主机；以 `.local` 结尾的主机；以及完全不含点的主机 —— 在家庭网络里那意味着一台
机器名。

**用户为之背书的主机。** 一份受信任主机列表，按精确名称或 `*.后缀` 模式。这是应用无法识别的网络的逃生
口 —— 有自己命名方式的 VPN，或者私有域名上的反向代理。

## 拒绝

到其他任何目标的明文 HTTP，以及既非 HTTP 也非 HTTPS 的任何协议。设置照常同步，被留下的只有密钥，界面会说明
这一点及其原因。

## 有讲究的细节

- **端口被忽略。** 决定因素是传输方式和目的地。
- **后缀匹配需要真实的子域。** `*.example.com` 信任 `a.example.com`，不信任 `example.com`。
- **后缀必须在末尾。** 像 `evil.ts.net.example.com` 这样的主机会被拒绝：它真正的后缀是 `.example.com`。
- **IPv4 映射的 IPv6 地址会先解包**再检查地址段，因此写成长形式的私有地址仍能被识别，公网地址也仍会被拒绝。
- **一次拒绝会同时挡住两个方向。** 下载密钥所走的连接和上传是同一条。

## 为什么这份列表是设备本地的

受信任主机列表不同步。同一个名称在这里解析到本网络的一台机器，在另一台设备上可能完全是别的东西，因此这个判
断属于将要发起连接的那台设备。保持本地也意味着一台设备的编辑不会悄悄让其余每台设备都开始上传密钥。
