# 选择路线

本地模型在哪个处理器上运行，以及这行不通时会发生什么。规则位于 `EngineRouter`，一个纯函数；本页的每个例子
都是 `test/engine_router_test.dart` 中的一个用例。

## 问题

一个任务指明一个本地模型，以及在什么上运行它：**自动**、**CPU**，或一条指名的路线。设备为该模型的模型包提供
若干路线 —— 每条是一个适配器、一个后端和一个处理器 —— 每条都带有检查结果。路由器的回答是一条要运行的路线，
或者一个说明为什么一条都不行的错误代码，同时附上其余每条路线被跳过的原因，这样页面可以说明某条路线为什么没
有提供，而不是把它藏起来。

三个承诺约束着每一个回答：

1. **模型绝不被替换。** 只考虑所选记录自己的模型包。要求 Whisper large-v3 的任务不会悄悄在 turbo 上运行，
   更不会在 Parakeet 上运行。
2. **回退只在用户的策略之内发生**，并作为一个独立的决定返回 —— 从哪里、到哪里、为什么 —— 由任务记录下来。
3. **自动从不选择一条没有理由信任的路线**（本地模型计划的决定 D20）。

## 规则，按顺序

1. **语言。** 带语言列表的模型只有在每个所要求的语言都在列表上时才接受任务，按主子标签比较（`zh-TW` 是中
   文）。Parakeet 列出 25 种欧洲语言，因此中文、日语或韩语的任务会以 `UNSUPPORTED_LANGUAGE` 失败，而不会到
   达它。没有列表的模型接受任何语言。
2. **本模型的路线。** 模型或模型包不属于该记录的路线被忽略。一条不剩时：若本构建有适配器能处理该记录的某个模
   型包，则为 `MODEL_MISSING`（适配器只为已安装的模型包描述路线，所以"什么都没安装"看起来就像"没有路线"），
   否则为 `BACKEND_NOT_BUILT`。
3. **可用的路线。** 路线在以下情况下被跳过：模型包未安装（`notInstalled`）、后端或驱动缺失
   （`unavailable`）、它在这里的检查崩溃了（`crashed`）或失败了（`checkFailed`），或者任务需要它不保留的片
   段时间（`lacksTimestamps`）。
4. **请求。**
   - **CPU**：最好的可用 CPU 路线 —— 通过检查的排在尚未检查的之前，其次是在此测试过的，再其次是依据更好的。
   - **指名的路线**：可用就用那条路线；否则按回退策略（见下文）处理，并附上该路线无法运行的原因。
   - **自动**：见下一节的规则。

在当前键下尚未检查过的选定路线会带着 `needsSmokeTest` 返回；任务先运行检查，检查失败就重新选路。

## 自动

自动考虑在本设备上通过了检查的加速器路线（GPU 和 NPU），并且只在以下情况下选用其中一条：

- 本项目**已在此类设备上测试过它**；或者
- 它的依据是 **A** 或 **B**，并且在它的检查中运行得**比 CPU 路线**在它自己的检查中**更快**。任何一方速度未
  知都不算胜出。

未测试的 **E** 或 **U** 路线从不被自动选中，无论它的检查有多快；只有用户指名时它才运行。在候选路线中，在此
测试过的排第一，其次是检查更快的，再其次是依据更好的，最后按路线键，因此选择是稳定的。没有候选时，自动选用
CPU 路线 —— 每台设备上的底线，无论在此测试过与否。连可用的 CPU 路线都没有时，任务失败。

### 示例

| 本设备上的路线（检查结果，速度以每秒音频所需秒数计） | 要求 | 结果 |
|---|---|---|
| CPU（通过，0.5，已测试）；GPU E（通过，0.9，已测试） | 自动 | GPU —— 在此测试过优先于速度 |
| CPU（通过，0.5）；GPU A 或 B（通过，0.2） | 自动 | GPU —— 有等级且更快 |
| CPU（通过，0.5）；GPU B（通过，0.8） | 自动 | CPU —— GPU `notFasterThanCpu` |
| CPU（通过，0.5）；GPU E 或 U（通过，0.01） | 自动 | CPU —— GPU `untestedForAuto` |
| CPU（通过，速度未知）；GPU A（通过，0.1） | 自动 | CPU —— 没有可比较的 |
| CPU（通过）；GPU（未检查，已测试） | 自动 | CPU —— GPU `notChecked` |
| CPU（通过）；OpenCL（通过，0.4，已测试）；QNN A（通过，0.1） | 自动 | OpenCL —— 在此测试过的优先 |
| CPU（未检查） | 自动 | CPU，在它的检查之后 |
| CPU（失败）；GPU E（通过，0.1） | 自动 | 失败 —— 绝不选未测试的 E 路线 |
| CPU；GPU E（通过） | 那条 GPU | 那条 GPU —— 用户选了它 |

## 回退

要求的路线无法运行时 —— 无论在任务开始前还是任务进行中 —— 由设备本地的回退策略决定：

- `sameModelOnCpu`（默认）：同一模型的 CPU 路线，记为一次回退；
- `none`：任务以该路线的错误代码失败；
- `systemRecognizer`：操作系统的系统语音识别，一条适配器为 `system`、不服务于任何特定模型的路线（后续里程
  碑）。

任务进行中，只有**路线问题**才能被接手 —— `BACKEND_NOT_BUILT`、`DRIVER_MISSING`、`DEVICE_UNAVAILABLE`、
`MODEL_COMPILE_FAILED`、`DEVICE_LOST`、`ROUTE_CRASHED`，或加速器上的 `OUT_OF_MEMORY`。损坏的模型或不支持的
语言在 CPU 上也会失败，所以任务失败；CPU 本身的失败已经无处可退。失败的那个窗口会在回退路线上重跑，回退记录
下它发生在哪个窗口。

## 检查

一条路线的本机检查会转写一段内容已知的短片段。它的文本在转成小写、去掉标点之后与预期的词比较，取一减去词错
误率；**达到 0.8 或以上**即通过（`smokeTestMinSimilarity`）。这让模型可以用不同方式写出一个数字或拆分一个复
合词而仍然通过，同时让产出另一句话或什么都没产出的路线失败 —— 坏掉的 GPU 内核通常就产出这些。检查还会记录路
线的速度，这正是自动所比较的。

结果按路线的六段式键存档（适配器版本、模型哈希、操作系统版本、驱动版本、处理器、精度），因此其中任何一项变
化都会要求重新检查。
