# 版本历史

新的在前。每条记录说明改了什么，以及在重要之处说明为什么 —— 事后最难还原的正是理由。

## 0.1.0 —— 未发布

第一个发布版本：录音进去，转写稿出来；应用知道如何切分一份大到无法整段发送的录音、从被打断的地方继续、在各
片之间保持说话人的同一身份，并拒绝把 API Key 送往不该送的地方。

**转写**

- 来源与模型成为一个库，带上每个模型的真实上限，以及每项能力的三态答案，因此"没有人验证过这一点"可以直说，
  而不是靠猜。
- 一个规划器，在任何上传之前决定如何切分录音并说明理由。那些原始脚本要求用户传入一个分段长度，事后才告诉他
  们行不行。
- 一个任务引擎，在每个窗口之后记录状态，因此中途关闭应用最多损失正在传输中的那一个窗口，继续时会复用一切已经
  付过费的部分。
- FFmpeg 在 Android、iOS 与 macOS 上链接进应用；在 Windows 上使用外部可执行文件并附带下载助手，因为维护中的
  插件只发布 x86_64 的 Windows 二进制。

**阅读**

- 一个双模式查看器：连续段落用于阅读，逐行视图用于修正。搜索、字号、说话人名字与颜色，以及一条可从某一句跳
  转并跟随播放的音频条。
- 六种导出格式。只有模型返回了真实时间时才提供字幕 —— 差一分钟的 SRT 看起来像是能用，比没有还糟。

**说话人**

- 基于两个窗口共享的秒数做跨窗口匹配，并把声音样本传给接受它们的服务方。
- 阈值宁可拒绝一次可疑的匹配，也不去猜；把两位说话人合并成一位只需点一下。错误的合并会让转写稿把话安错人，且
  事后没有任何东西会揭示它；漏掉的合并只是列表里多出一位说话人。

**密钥**

- API Key 只在 HTTPS 下、或在明文 HTTP 到一个无法离开用户自己网络的地址时，才会送往 WebDAV 服务器 —— 私有地
  址段、Tailscale 或 ZeroTier 名称、mDNS 名称，或者他们在该设备上信任的主机。其余内容照常同步。
- 被拒绝的地址不会产生任何请求，两个方向都不会。

**外壳与约定**

- 三个标签页 —— 转写、库、设置 —— 建立在单个 `go_router` `ShellRoute` 之上，从 600 逻辑像素起使用导航栏、以
  下使用底部栏，两者由同一份目的地列表构建，因此不会各走各的。
- `FlexScheme.tealM3`，选它是为了一眼就能与四个兄弟应用区分开。
- 英语、简体中文与繁体中文的本地化，并有测试在词条互相偏离、译文改了占位符名称、或中文词条里仍留着英文时
  失败。
- 系列的自适应布局策略模块，核心逐条照搬，并扩展了本应用自己的分栏规则。它们的推导在 `adaptive-layout.md`。

**数据**

- 一个会同步的数据模块 `transcribe_settings.json`，把来源、模型与默认值作为一列带不透明载荷的扁平记录保
  存 —— 这样新版本写入的记录在这里也能正确合并，即便本版本无法解释它。
- `myapps_data` v1.0.2 之上的四个共享服务外观层，以及 WebDAV、备份、许可证与隐私页面。
- API Key 与任务目录有意**不是**数据模块，这正是它们在结构上（而非靠过滤）被排除在同步、备份与 ZIP 导出之外
  的原因。

**值得记住的决定**

- 设置合并判断两次编辑是否"相同"，依据的是记录的 id、kind 与 payload，**而不是**时间戳。两台设备相隔一分钟把
  同一个来源改成同样的名字，并没有产生任何分歧，否则共享引擎会在两份一模一样的配置之间报出冲突。
- Windows 使用外部 FFmpeg 可执行文件而不是插件自带的库，因为维护中的插件只发布 x86_64 的 Windows 二进制，而
  本项目是在 Windows on ARM64 上开发的。`platform-notes.md` 记录了整套安排。

**由测试而非用户发现的缺陷**

- 中途失败或被取消的任务，是从它**开始时**的那份记录写回的，抹掉了方案和所有已完成的窗口。下一次运行会把它们
  全部再付一遍钱 —— 而那正是续传存在要防止的唯一一件事。
- 原子写入是一次重命名，而在 Windows 上，只要有别的东西持有该文件，重命名就会直接失败 —— 正在读取它的任务列
  表、杀毒软件、搜索索引器。一次持续一毫秒的冲突就可能杀掉一个一小时的任务。现在读写都会重试。
- 加方括号的公网 IPv6 地址不含点，因此落到了"把无点主机视为本地"的规则上，本会被当作可以发送密钥的安全去处。
