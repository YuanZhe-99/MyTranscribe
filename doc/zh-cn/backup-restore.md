# 备份、恢复与 ZIP 传输

保留配置副本有两种方式：留在设备上的本地备份包，以及用户可以随意存放的 ZIP 文件。两者携带的**只有**模块
注册表列出的内容：设置文件和转写投影。两者都不携带 API Key 或录音。

引擎位于共享的 `myapps_data` 包中；本页说明它们在这里是如何配置的。

## 本地备份

一次备份是 `backups/` 下的一个 JSON 备份包，名为 `backup_<yyyyMMdd_HHmmss>.json`，保存每个已注册数据文件
的原始内容。MyTranscribe 没有图片，因此该格式同时支持的数据块存储在这里始终为空。

- **自动：** 若用户开启，每天一次；在启动时、恢复前台时和周期性心跳时检查，因此跨过午夜仍开着的设备也能
  拿到一份。
- **保留期：** 用户选定的天数，或永久保留。每次新建备份后执行清理。
- **列表：** 新的在前，带大小；无法解析的备份包会被标为损坏而不是隐藏 —— 一份恢复不了的备份，值得在你需要
  它之前就知道。

### 恢复

用户选择一个备份包，以及要从中恢复哪些模块。然后按顺序：

1. 在**第一次写入之前**关闭 WebDAV 自动同步。恢复会用较旧的数据替换本地数据；中途触发的同步会把恢复到一半
   的状态上传上去。
2. 每个选中的载荷都通过解析来验证。验证失败的备份包会被拒绝，且什么都不写。
3. 文件以原子方式写入。
4. **只有在恢复失败且什么都没写**的情况下才重新开启自动同步。恢复成功之后会询问用户是否上传恢复后的状态，
   因为那是关于其他设备的决定，不是关于这一台的。

这个顺序是共享包的不变量 I5，不由我们更改。

## ZIP 导出与导入

`mytranscribe_export_<yyyyMMdd_HHmmss>.zip` 只包含已注册的数据文件，别无其他。引擎在这里配置得很严格，因为
这个应用没有需要迁就的存量用户：

- 未知条目会被拒绝，而不是忽略，
- 载荷必须是合法的 UTF-8，
- 一切在写入任何东西之前先验证，
- 写入是原子的。

导入分两个阶段：先对整个归档分类并验证，然后写入。被拒绝的归档不会动到现有设置。无论上述设置如何，引擎都
会直接拒绝路径穿越；每个条目在写入前都会重新校验其解析结果位于应用目录之内。

导出会请求一个目录；导入会请求一个 `.zip` 并再次确认，因为导入会替换现有内容。

## 有意不包含的内容

- **API Key。** 备份包是一个普通的 JSON 文件，用户可能复制它、邮件发给自己，或者在借来的机器上恢复。密钥
  到达新设备的途径是一次安全的同步，或者手工输入。这是一个用户应当知道的取舍：在全新设备上恢复备份会拿回你
  的来源和模型，但密钥需要重新输入。
- **录音与音频。** 每个备份包里都塞进几小时的私人音频，备份包也就不再是可以随手复制的东西了。每条转写的
  **文本**通过转写模块包含在内，声音则不包含。
- **`webdav_config.json` 与 `storage_config.json`。** 服务器凭据，以及描述**这一台**设备的偏好。
- **下载的模型与引擎状态。** 一个模型动辄数 GB，而且可以重新下载；本地模型的**记录**在设置模块里，会像来
  源一样恢复，因此恢复后的设备会把它的模型列为未下载。`local_engine_state.json` 描述的是这台设备的处理器，
  放到别处毫无意义。

这些都是结构性排除：引擎只接触注册表里的文件名。

恢复转写模块时**只增不删**。备份包里有的内容会写入 `jobs/`，但不会因为某条转写没出现在包里就把本地的删
掉：备份包说的是它被创建时有什么，而不是用户之后删掉了什么。导入 ZIP 同理。

还有一条兼容性说明：0.2.0 版本会忽略备份包里的新模块，但它的 ZIP 导入对未知条目很严格，会**拒绝**本版本
导出的压缩包。
