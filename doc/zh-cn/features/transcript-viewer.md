# 阅读转写稿

*由里程碑 M4 交付。*

查看器是转写稿不再只是一个文件、而变成可以阅读、修正并发送出去的东西的地方。它是一条整窗路由：转写稿需要整
个窗口，而且它是针对某一份录音做的事，做完就离开。

## 两种阅读方式

- **全文** —— 连续的段落。录音有说话人时，同一个人连续的分句会合并成一段，顶部带上他的名字和颜色。这是阅
  读视图。
- **分句** —— 每个分句一行，各自带时间范围。这是修正视图：点一行去听它、编辑它的文字，或者把它移给另一位
  说话人。

合并、时间显示与字号都是偏好，按设备记住。

## 与音频并排

底部有一条播放条：播放与暂停、跳转、进度条和倍速。点任意一句都会跳到那里，播放头所在的句子会高亮。所用音频
是任务已经做好的转换副本，因此不必保留原文件也能播放。

小到可以整段上传的录音从来就没有转换副本，用户主动删掉副本的任务也不再有；这两种情况下，只要还找得到原始录
音，就改用它播放。只有两者都不在设备上时，播放条才会说没有可播放的内容。

## 说话人

模型返回了说话人标签时，会有一个面板列出他们，附带颜色、名字，以及各自说了多少。名字由你来定。真正是同一个
人的两位说话人可以合并，某一句归错了人则在句子编辑器里移走。批量把一位说话人拆成两位没有做：逐句移动能完成
同样的事，在有人真的遇到这样不够用的录音之前，批量操作只是对他们想要什么的猜测。

每一次修改都会在做出的那一刻写入磁盘，下次打开这份转写稿时会重新读出来。这里的一切都不会重写文字：分句指向
说话人，因此重命名、合并或归为未知都只改动一条记录，所有段落随之改变。由于原始回复被
保留下来，说话人匹配也可以从头重跑，无需再次上传任何东西。

## 导出

导出的文件以这次转写命名 —— 用户给它起的名字，若没起过则用录音的名字。复制、保存或分享，按合适的格式：

| 格式 | 用于 |
|---|---|
| 纯文本 | 粘贴到别处 |
| Markdown | 笔记，带说话人与时间 |
| SRT、VTT | 字幕 |
| JSON | 另一个程序 |
| CSV | 电子表格 |

字幕格式需要时间戳，因此只有模型返回了时间戳时才提供，并显示原因，而不是让选项悄悄消失。

## 没有时间戳时

有些模型只返回文字。转写稿依然可用：时间显示为估算值，取自每个窗口的起点；跳转会跳到窗口开头；需要真实时间
的格式不可用。查看器会说明这几点各自适用哪一条，而不是假装自己有它并不具备的精度。

## 窗口较窄时

说话人面板与显示面板移入可上拉的抽屉，转写稿保持整幅宽度。做出这一判断的是一道双重门槛 —— 窗口既要有分成
两栏的形状，**又要**有容纳两者的宽度 —— 在 [`../adaptive-layout.md`](../adaptive-layout.md) 中有说明。
