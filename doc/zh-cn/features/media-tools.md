# 媒体工具

*由里程碑 M1 交付。*

切分录音、读取时长、截取说话人样本，都需要 FFmpeg。一个接口 `MediaToolkit` 描述应用需要什么，两个实现提供
它。

## 应用要求的能力

- **探测** —— 时长、码率、编解码器、是否有视频
- **转换** —— 把整段录音转成单声道 16 kHz 64 kbps MP3，带进度
- **截取窗口** —— 从转换后的文件中原样复制一段时间范围，不重新编码
- **截取样本** —— 几秒的 16 kHz 单声道 WAV，用于说话人注册

每个耗时操作都会报告进度，并且可以取消。

## 转换一次，切分多次

本应用取代的那些脚本，每个窗口都要把源文件解码一遍。改成只解一次有三个值得说明的后果：一次解码而不是 n
次；分段大小可以按每秒 8000 字节精确预测；转换后的文件还兼作转写稿查看器的播放副本，并且在系统清掉所选文件
缓存之后依然存在。画质完全相同 —— 两种做法用的是同一套编码参数。

已经足够小、且格式为模型所接受的录音会原样上传，完全不经过 FFmpeg。对短片段而言这是常见情形，也是那些脚本
同样具备的快路径。

## 两种后端

**内嵌**（Android、iOS、macOS）：FFmpeg 库链接进应用。进度来自库自身的统计回调；取消即取消该会话。

**外部可执行文件**（Windows）：`ffmpeg` 与 `ffprobe` 作为子进程运行。进度从 FFmpeg 在 stdout 上的机器可读
进度流解析；stderr 的最后若干行会保留，以便失败时能说出出了什么问题；取消会杀掉进程并删除未完成的输出。

调用哪一个由 `platform_capabilities.dart` 决定，其中的理由 —— 包括为什么在本项目自己的硬件上 Windows 用不
了那个插件 —— 见 [`../platform-notes.md`](../platform-notes.md)。

## 找到工具

Windows 上的顺序：用户设定的路径、应用的 support 目录、可执行文件所在目录及其 `bin/`、工作目录，然后是
`PATH`。候选项是通过文件是否存在来判断的，而不是运行它，因为运行一个可执行文件来测试会闪出一个控制台窗口。

什么都没找到时，设置页会直说，并提供两条路：下载一份已发布的构建，或者指向你已有的那一份。下载会取对应架构
的版本，只解出那两个可执行文件，验证它们能运行，并记录下载了什么。

在工具就绪之前应用并没有坏 —— 它仍然可以转写一份小到能整个上传的录音。需要切分的任务会失败，并给出一条点名
缺失工具、并提供去设置它的消息，而不是一个笼统的错误。
