# API Key，以及它们何时被允许离开本机

*由里程碑 M6 交付。规则及其理由先在这里定下来，因为这是隐私政策中对用户作出的承诺。*

## 密钥放在哪里

在应用目录下的 `transcribe_secrets.json` 中，以来源的记录 id 为键，因此密钥跟随它的来源。明文保存，与旁边
的 WebDAV 密码一样，隐私政策中也如此写明。

该文件**不是**数据模块。同步、备份与 ZIP 引擎只会接触 `lib/app/data_modules.dart` 中注册表里的文件名，因此
密钥不可能意外出现在备份包或 ZIP 导出里 —— 不是因为有什么东西把它过滤掉了，而是因为根本没有任何东西看过这个
文件。这正是密钥没有直接做成来源记录上一个字段的全部原因。

## 规则

只有当应用能安全地访问用户的 WebDAV 服务器时，密钥才会被复制过去。

**允许：**

- `https://` —— 任何主机。传输是加密的，问题到此为止。
- `http://` 到一个无法离开用户自己网络或覆盖网络的地址：
  - 回环：`localhost`、`127.0.0.0/8`、`::1`
  - 私有 IPv4：`10/8`、`172.16/12`、`192.168/16`
  - 链路本地：`169.254/16`、`fe80::/10`
  - 运营商级 NAT：`100.64/10` —— Tailscale 分配的地址段
  - IPv6 唯一本地地址：`fc00::/7`，涵盖 Tailscale 自己的范围
  - Tailscale 名称：任何以 `.ts.net` 结尾的主机
  - ZeroTier 名称：任何以 `.et.net` 结尾的主机
  - 本地名称：任何以 `.local` 结尾的主机，或完全不含点的主机
- `http://` 到用户加入其**受信任主机**列表的主机，按精确名称或按 `*.后缀`。

**拒绝：** 到其他任何目标的明文 HTTP，以及其他任何协议。

端口被忽略：决定因素是传输方式和目的地，不是端口号。

该检查写成一个纯函数，每个判定都带具名的理由，这样界面能说出**为什么**，而不只是能或不能；也让整张表可以在
没有网络的情况下被测试。后缀匹配要求真实的子域：`*.example.com` 信任 `a.example.com` 而不信任
`example.com`；像 `evil.ts.net.example.com` 这样的主机会被拒绝，因为它的后缀并不是 `.ts.net`。

## 用户看到什么

服务器地址输入框下方有一条随输入更新的横幅：

- 绿色 —— "API Key 会同步"，并说明理由（通过 HTTPS；在你的本地网络上；通过 Tailscale）。
- 琥珀色 —— "API Key 只保留在本设备"，并说明理由以及可以怎么办。**设置照常同步**，被留下的只有密钥。

已配置区域中有一行显示有多少来源保存了密钥，以及上次交换发生了什么。受信任主机编辑器就在旁边，添加一个主机
会立刻重新计算横幅。

## 交换过程

在 WebDAV 外观层内、同步引擎返回之后立刻运行，面向同一台服务器与同一个远端目录：

1. 评估端点。若被拒绝，就停止 —— **两个方向都停**。下载所走的连接和上传是同一条。
2. 下载远端的密钥文件，保留它的版本标记。
3. 按键以 `updatedAt` 合并，后写者胜，墓碑也参与，这样被删除的密钥不会回来。
4. 若有变化就写到本地，然后以读到的版本标记为条件上传。若服务器表示它已在我们脚下变过，就再读一次并重新合并
   一次。

强制上传与强制下载会在对应方向上跳过合并，与数据模块的做法一致。

**为什么它在引擎的锁之外运行。** 那把锁保护的是一次三路合并，其基线快照不能在脚下移动。密钥文件没有基线快
照，也没有合并状态 —— 它是一组彼此独立、按键存放的值 —— 而条件式上传把并发写入变成一次拒绝加一次重试，而不
是一次丢失的更新。把这次交换放进上锁的时间窗内，就意味着为了没有增加的安全性去改动四个应用共用的引擎。

## 这个取舍

密钥被排除在本地备份之外。在全新设备上恢复备份会拿回你的来源和模型，密钥需要重新输入 —— 或者从一台已有密钥
的设备上，经由符合条件的连接同步一次。这是有意的选择：备份包是人们会到处复制的普通文件，其中的密钥，在它的
每一份副本里都是密钥。
