# 个人资料

一个名称和一个圆形头像，在你同步的每台设备上保持一致。

## 用户看到什么

- **首页标签。** 头像位于"转写"标签标题的左侧，只在这里出现。点击它会打开设置。
- **设置顶部。** 一行头像加名称，是列表的第一项。点击会打开对话框，可选择或移除头像、编辑名称。更换头像
  立即保存；名称在点击"保存"时保存。
- **没有图片时**，头像显示名称的首字母；连名称也没有时显示人像图标。尚未通过同步到达的图片显示同样的占位，
  文件到达本机后替换它。

## 如何存储

`profile.json`（见 [data-formats.md](../data-formats.md)）保存名称和头像路径，各自带有自己的时间戳。图片是
`images/avatar_<uuid>.jpg`，先校正照片方向，再居中裁剪为 512 x 512 的正方形 JPEG。每次更换头像都使用**新的
文件名**：引擎的图片阶段是增量的，从不覆盖同名文件，复用文件名会让其他设备一直停留在旧图片上。旧文件只在本
机删除，并且仅当文件名以 `avatar_` 开头时才删。旧图片会留在服务器上，这是已知限制。

所有编辑都经过同一个排队的"读取—修改—写入"，只有字节确实变化时保存才会通知自动同步。已存在但无法解析的
`profile.json` 绝不会被覆盖。

## 如何同步

个人资料是第三个数据模块，追加在设置和转写之后。它按字段合并，后写者胜，平局保留本地值，不会产生冲突。
`referencedImages` 指明头像，引擎的 `images/` 阶段正是据此传输图片；MyTranscribe 自己的 `audio/` 旁路与此
无关，也不受影响。详见 [sync.md](../sync.md)。每当自动同步报告本地数据已变化，provider 就会重新读取个人资料，
手动同步和恢复也包含在内。

## 备份与恢复

个人资料是备份包和 ZIP 导出中的一个模块，在恢复对话框里标为"个人资料"；头像图片以数据块形式传输。旧备份
没有个人资料，恢复时不会触碰它。
