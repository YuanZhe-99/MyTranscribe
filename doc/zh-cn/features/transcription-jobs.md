# 转写任务

*由里程碑 M3 交付。*

一个**任务**就是一份录音被转成文字的过程。它是磁盘上的一条记录，而不只是一个正在运行的任务，这正是它能在
应用被关闭后幸存、并从停下的地方继续的原因。

## 阶段

```
排队 -> 探测 -> 规划 -> 转换 -> [ 切分 -> 上传 -> 解析 ]* -> 合并
     -> 匹配说话人 -> 渲染 -> 完成
```

任何阶段都可能失败或被取消。失败或取消的任务会保留已完成的分段，因此继续时不会为它们再付一次费。

- **探测**读取录音的时长与码率。没有媒体工具时这一步被跳过，只有文件大小可以为方案提供依据。
- **规划**决定是否切分，以及切成什么样。见
  [`../algorithms/chunk-planner.md`](../algorithms/chunk-planner.md)。
- **转换**把整段录音转换一次；文件原样上传时会跳过。
- **切分、上传、解析**每个窗口各运行一次，按顺序，一次一个。每完成一个就重写任务记录，并保留服务方的原始
  回复。
- 对**本地模型**来说，状态机相同，只有三处不同（见 [`local-models.md`](local-models.md)）：路线在**规划**
  时、在方案之前选定，因为它的限制和模型包修订版都要进入方案；每个窗口切成 PCM；**转写**取代上传，模型在整
  个任务中只加载一次。
- **合并**把各窗口拼回一份转写稿。见
  [`../algorithms/overlap-merge.md`](../algorithms/overlap-merge.md)。
- **匹配说话人**只在模型返回了说话人标签时运行。见
  [`diarization-and-speakers.md`](diarization-and-speakers.md)。
- **渲染**写出转写稿与所需的输出文件，然后删除分段音频，除非用户选择保留。此刻若某个分段正被别的程序占
  用，删除会失败；它会在应用下次启动时被清扫掉，而不是以录音十分之一的体积长期留在任务目录里。

## 继续

继续时会重新计算方案的指纹 —— 来源、模型、窗口长度、重叠、语言、提示词、关键词、是否要求说话人。若它不再
匹配，所有缓存的分段结果都会被丢弃：在不同设置下产生的结果不是用户此刻要的结果。这与那些脚本在进度文件与当
前参数不符时采取的规则相同。

当某个分段保存的结果与磁盘上该窗口文件的大小一致时，它会被复用。窗口文件缺失就从转换后的音频重新切一次，代
价很低。转换后的文件缺失就从源文件重建；若源文件本身没了，任务失败并如实说明。

## 一次一个

任务在队列中一次运行一个，任务内的各窗口顺序上传。这让续传顺序保持简单，也尊重服务方的速率限制。切分一个窗
口相对上传它而言开销很低，把两者重叠所得甚少。

任务运行期间屏幕保持常亮，并在每条退出路径上释放，包括失败与取消。

## 出问题时

- 网络故障、超时或服务器错误：重试两次，延迟递增。
- 触发速率限制：重试，并遵守服务器要求的等待时间。
- 被服务器拒绝：不重试。展示服务器自己的消息，因为它通常正好说清了问题所在 —— 密钥不对、文件太大、格式不
  支持。
- 拒绝信息中点名了模型不具备的某项功能（例如说话人标签）时，会提供"不带该功能再试一次"，而不是让用户自己去
  找那个设置。
- 某个窗口切出来后发现超过上传上限，会改用更小的窗口重新规划，而不是失败。
- 本地模型未下载、已损坏、不能处理该语言、没有本构建能运行的路线，或者内存不足时，任务以专属的失败类型结
  束 —— `modelNotInstalled`、`modelDamaged`、`unsupportedByModel`、`engineUnavailable`、`outOfMemory` ——
  并附上引擎自己的原话，而不是去怪一台根本没有联系过的服务器。
- 本地路线中途失败 —— GPU 丢失、驱动缺失 —— 时，若回退策略允许，就改到 CPU 上，在那里重跑同一个窗口，并把
  这次改动写进任务。如果应用本身在某条路线里停掉了，下次启动会察觉，把该路线在本设备上记为崩溃，并以原因
  `ROUTE_CRASHED` 在另一条路线上继续这个任务。

## 页面看着什么

任何时刻一个任务都有三份副本：磁盘上的记录、执行器手里正在处理的那一份，以及页面上一次读到的那一份。页面取
三者中最后写入的那一份，于是谁都不必知道另外两个的存在。

执行器会保留刚刚结束的那个任务，好让正在显示它的页面立刻就能说出结果；它还会为自己写下的每一条记录计数。列
表和详情页盯着这个计数并重新读取。在这个计数存在之前，只有当某个页面因为按钮被按下而恰好刷新了列表时，记录
才会被重新读取 —— 所以一个在自己页面开着的时候完成的任务，会一直显示它开始时的阶段，还带着一个"开始"按
钮，直到应用重启为止。按下那个按钮会从各分段重新生成转写稿，把所有修正统统丢掉。

因此已完成的任务提供的是**重新转写**，绝不是单纯的"开始"；而重新转写会先询问：转写稿要从头生成，说话人名称
和改过的句子都会消失。

## 输出

`<名称>.transcript.md` 与 `<名称>.transcript.txt`，采用那些脚本产生的格式；在桌面端当源录音所在目录可写时
写在它旁边，否则写进任务自己的导出目录。其他格式由查看器提供。

两个文件都采用跨窗口匹配最终确定的说话人名字，因此同一个人从头到尾只有一个名字，而不是各个窗口各叫各的。没
有人命名过的说话人在那里是英文的 `Speaker 1`，因为执行器没有界面语言可问。它们以**录音**命名，而不是以用户
后来给这次转写起的名字命名：这样一个文件夹里的这些文件是靠文件名来读的。

## 为转写命名

在有人另行命名之前，一次转写以它的录音为名。名字可以在详情页修改，或长按列表中的一行修改；清空它就会把录音
的文件名换回来。

它只是一个标签，仅此而已。写在录音旁边的那两个文件（只有在该选项开启时才会写，它默认关闭）保留录音自己的名字，因为一个文件夹里的这些文件是靠文件名
来读的，而在应用内改个名字不构成重命名磁盘文件的理由。从查看器导出的文件则会采用这个名字，因为那是用户有意
要保存到某处的文件 —— 其中文件名不允许出现的字符会被替换成下划线。每份渲染出来的转写稿里的 `- Audio:` 一
行，始终写的是录音。

任务正在运行时也可以改名。执行器会把这个名字重新应用到它写出的每一份内容上，因此它不会在下一个分段完成时被
覆盖掉。

## 一次转写占用了什么

详情页会说明这个任务在本设备上占多少空间，并在转写稿已经存在之后，提供删除录音转换副本的选项。那份副本大约
是原文件的三分之一 —— 一场八十分钟的讲座约三十九兆 —— 保留它是因为查看器要用它播放。删除它之后，记录、转写
稿、原始回复和说话人样本都还在，因此转写稿仍可阅读、仍可修正，说话人匹配也仍可在不上传任何内容的情况下重
跑。播放会回退到原始录音。

任务正在运行时不提供这个选项，因为各个分段正是从它切出来的。
