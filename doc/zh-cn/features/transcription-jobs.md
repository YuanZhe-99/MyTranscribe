# 转写任务

*由里程碑 M3 交付。*

一个**任务**就是一份录音被转成文字的过程。它是磁盘上的一条记录，而不只是一个正在运行的任务，这正是它能在
应用被关闭后幸存、并从停下的地方继续的原因。

## 阶段

```
排队 -> 探测 -> 规划 -> 转换 -> [ 切分 -> 上传 -> 解析 ]* -> 合并
     -> 匹配说话人 -> 渲染 -> 完成
```

任何阶段都可能失败或被取消。失败或取消的任务会保留已完成的分段，因此继续时不会为它们再付一次费。

- **探测**读取录音的时长与码率。没有媒体工具时这一步被跳过，只有文件大小可以为方案提供依据。
- **规划**决定是否切分，以及切成什么样。见
  [`../algorithms/chunk-planner.md`](../algorithms/chunk-planner.md)。
- **转换**把整段录音转换一次；文件原样上传时会跳过。
- **切分、上传、解析**每个窗口各运行一次，按顺序，一次一个。每完成一个就重写任务记录，并保留服务方的原始
  回复。
- **合并**把各窗口拼回一份转写稿。见
  [`../algorithms/overlap-merge.md`](../algorithms/overlap-merge.md)。
- **匹配说话人**只在模型返回了说话人标签时运行。见
  [`diarization-and-speakers.md`](diarization-and-speakers.md)。
- **渲染**写出转写稿与所需的输出文件，然后删除分段音频，除非用户选择保留。

## 继续

继续时会重新计算方案的指纹 —— 来源、模型、窗口长度、重叠、语言、提示词、关键词、是否要求说话人。若它不再
匹配，所有缓存的分段结果都会被丢弃：在不同设置下产生的结果不是用户此刻要的结果。这与那些脚本在进度文件与当
前参数不符时采取的规则相同。

当某个分段保存的结果与磁盘上该窗口文件的大小一致时，它会被复用。窗口文件缺失就从转换后的音频重新切一次，代
价很低。转换后的文件缺失就从源文件重建；若源文件本身没了，任务失败并如实说明。

## 一次一个

任务在队列中一次运行一个，任务内的各窗口顺序上传。这让续传顺序保持简单，也尊重服务方的速率限制。切分一个窗
口相对上传它而言开销很低，把两者重叠所得甚少。

任务运行期间屏幕保持常亮，并在每条退出路径上释放，包括失败与取消。

## 出问题时

- 网络故障、超时或服务器错误：重试两次，延迟递增。
- 触发速率限制：重试，并遵守服务器要求的等待时间。
- 被服务器拒绝：不重试。展示服务器自己的消息，因为它通常正好说清了问题所在 —— 密钥不对、文件太大、格式不
  支持。
- 拒绝信息中点名了模型不具备的某项功能（例如说话人标签）时，会提供"不带该功能再试一次"，而不是让用户自己去
  找那个设置。
- 某个窗口切出来后发现超过上传上限，会改用更小的窗口重新规划，而不是失败。

## 输出

`<名称>.transcript.md` 与 `<名称>.transcript.txt`，采用那些脚本产生的格式；在桌面端当源录音所在目录可写时
写在它旁边，否则写进任务自己的导出目录。其他格式由查看器提供。
