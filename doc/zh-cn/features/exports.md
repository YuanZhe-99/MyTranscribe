# 导出

*由里程碑 M4 交付。*

一份完成的转写稿可以用六种格式离开应用。提供哪几种，取决于模型实际返回了什么，而不是取决于当初要求了什么。

## 格式

| 格式 | 用途 | 说话人的呈现方式 |
|---|---|---|
| TXT | 阅读，粘贴到任何地方 | `名字：所说的话`，每段一位说话人的连续发言 |
| Markdown | 一份文档，或一个已经放着脚本输出的文件夹 | `**名字** [mm:ss]：` 段落；无人被识别时则是 `## Segment n` 标题 |
| SRT | 字幕，给能读 SubRip 的播放器 | 名字单独一行，位于文字上方 |
| VTT | 字幕，给网页 | 一个 `<v 名字>` 标签，播放器可按说话人分别设定样式 |
| JSON | 全部内容，包括应用自己的字段 | 按存储原样 |
| CSV | 电子表格 | 一列 |

没有说话人的转写稿，其 Markdown 形态刻意与那些原始 Python 脚本写出的完全一致。手里同时有那些脚本产出的一批
转写稿和本应用产出的一批的人，应该分不出哪批是哪批。

任务完成时还可以在录音本身旁边写两个文件。该功能**默认关闭**，开关在设置 › 转写：应用过去不问自答地这么
做，把文件留在录音当时所在的任意文件夹里 —— 而那个文件夹用户很可能早就搬走或清空了。无论开关如何，转写稿
本身都保存在任务自己的文件夹里。

那两个文件用的是同一套渲染器，因此它们与导出说的是同样的内容、同样的形态。只有两处不同，且都是刻意的：那两
个文件带有任务自己的表头条目；未命名的说话人在那里是英文的 `Speaker 1`，没有人被记名的句子同样是英文的
`Unknown`，因为任务执行器没有界面语言可问。它们也是转写稿在任务结束那一刻的快照 —— 之后在查看器里做的修正要从查看器导出，没有任
何东西会背着用户去改写录音旁边的文件。

## 字幕需要真实时间

不返回时间戳的模型仍然能产出一份完全可读的转写稿：显示的时间是应用自己的估算，取自每个窗口的起点，查看器也会
如实说明。

这些估算不能变成字幕文件。差一分钟的字幕看起来像是能用，比没有还糟，因此 SRT 与 VTT 会以**禁用**状态并附带
原因呈现，而不是隐藏起来。隐藏只会让用户去找一个并不存在的选项。

## 文件所说的与屏幕所说的一致

说话人的名字来自查看器，不是来自磁盘上的文件，因此刚刚输入的名字会立刻出现在导出里。合并、改派、修正过的句
子同理。

## 它去哪里

每次导出都先写进任务自己的 `exports/` 目录。然后：

- **在 Windows 与 macOS 上**，会有一个保存对话框询问放在哪里。取消对话框仍会在导出目录留下副本，工作不会
  丢。
- **在 Android 与 iOS 上**，没有保存对话框，由系统分享面板接手。

CSV 会带一个字节序标记写出。没有它，Windows 上的 Excel 打开中文转写稿会是乱码，而 Windows 上的 Excel 正是
这些文件多半会被打开的地方。

## 复制

复制按钮把整份转写稿以纯文本形态放进剪贴板 —— 按说话人合并并带上名字，也就是读者看到的样子，而不是原始的分
句。
