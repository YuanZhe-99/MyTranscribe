# 本地模型

本地模型在设备上转写录音：不需要密钥，模型一旦在磁盘上就不需要网络，音频也从不离开设备。本页描述目前已经
建成的部分 —— 记录、模型包、路线、检查和任务 —— 并说明哪一块会在 `PLAN.md` 的后续里程碑中到来。

**L0 阶段的状态：** 协议、记录、模型包管理器、路由器、设备本地状态，以及任务执行器的本地路径都已就位，并用
一个假引擎测试过。目前还没有编译进任何原生引擎（whisper.cpp 在 L1 到来），因此引擎注册表是空的，本地任务会
以"此构建没有设备端引擎"失败。选择和下载模型的页面随 L1 一起到来。

## 记录与模型包

本地模型是 `transcribe_settings.json` 中一条 kind 为 `localModel` 的同步记录，与来源和模型并列（见
[`data-formats.md`](../data-formats.md)）。它只保存在每台设备上都成立的内容：名称、系列（`whisper`、
`parakeet`、`qwen`、`custom`）、它能转写的语言、窗口上限、它的能力，以及它可以使用的各**模型包**
（artifact）的 id，按适配器列出。某个模型包是否已下载、放在哪里、由哪个处理器运行，都是关于某一台设备的事
实，存放在设备本地的文件里。因此在桌面上添加的模型，在手机上显示为"未下载"，而不是一个许诺。

每个本地模型 id 都以 `local:` 开头 —— 内置模型如 `local:whisper-large-v3-turbo`，用户从文件添加的模型则是
`local:` 加一个 uuid。这个前缀对旧版本很重要：0.2.x 把未知的 kind 读作 `unknown`，也以 `unknown` 写回，而
本版本正是靠这个前缀把这样的记录重新认作本地模型（见 [`sync.md`](../sync.md)）。

一条记录，多个模型包。Whisper large-v3 turbo 列出一个供 whisper.cpp 使用的 GGML 文件；后续里程碑会往同一条
记录里加入一个 Qualcomm 模型包。路由器挑模型包，用户挑模型。路由器从不挑另一个模型 —— Turbo 不是 large-v3，
要求其中一个的任务绝不会悄悄运行另一个。

| 模型 | 系列 | 模型包 | 下载大小 | 时间戳 | 语言 |

当设置文档里一个本地模型都没有时 —— 全新安装，或升级后的首次启动 —— 会用派生 id 预置内置模型，这样两台设备
预置出完全相同的记录，首次同步会把它们合并。模板的刷新方式与来源模板相同：用户从未改过的字段跟随更新的模
板。

## 下载模型包

模型包的清单列出每个文件的确切大小、SHA-256，以及它唯一允许的来源 URL，并固定在某个修订版上：Whisper 文件
固定到一个 Hugging Face 提交，sherpa-onnx 压缩包固定到一个 GitHub release 资源。这些哈希是托管方自己公布的
—— Hugging Face 的 LFS 对象 id，即文件字节的 SHA-256，以及 GitHub 的资源摘要 —— 下载器逐个文件核对，因此托
管方替换了文件时会明确失败，而不是装上别的东西。应用只在用户要求下载时才联系模型托管方，而且只访问清单里的
URL。

一次安装：

1. **检查空间**，下载、解包后的压缩包内容和安装分别计算 —— 压缩包在被删除之前与其内容并排存放。磁盘上已有的
   未完成下载不重复计算。平台给不出可用空间数字时，写入本身的磁盘已满错误就是检查。
2. **下载每个文件**，用 HTTP range 请求续传未完成的文件。服务器忽略 range、发来整个文件时，就从头开始。大小
   或哈希不对的文件会被删除而不是续传：一段损坏的前缀会让之后的每次尝试都损坏。
3. **解包**压缩包（Core ML 编码器用 ZIP，sherpa-onnx 用 `tar.bz2`），只在压缩包自身的哈希匹配之后进行，并
   在设备上为每个解包出来的文件计算哈希。
4. 在暂存文件夹里**组装**模型包，再一步**重命名**为 `models/<artifactId>/`，写入记录安装内容的
   `manifest.json`。装了一半的模型包永远不会以它自己的名字存在，失败的更新会让先前的版本原样保留。

运行中的任务会**租用**它的模型包。租用期间，模型包既不能被替换也不能被移除。取消的下载会保留未完成的文件，
因此下次尝试会续传它。"校验"会按清单再为已安装的文件计算一次哈希。

在 iOS 与 macOS 上，模型放在缓存目录里，iCloud 备份和 Time Machine 都不包含那里 —— 模型是可以重新下载的缓
存。空间不足时系统可能清掉这个目录，此时该模型显示为未下载。在 Android 与 Windows 上，模型放在应用目录下，
因此自定义存储路径会把它们一并带走。桌面用户可以把模型指向另一个文件夹。

## 路线、依据与"已在此类设备上测试"

**路线**是这台设备运行一个模型包的一种方式：一个适配器、一个后端（`cpu`、`metal`、`opencl`、`vulkan`、
`coreml`、`qnn`），以及它驱动的处理器（CPU、GPU 或 NPU）。各适配器针对这里已安装的模型包描述它们能运行的路
线；注册表为每条路线附上本设备的检查结果。

每条路线带有两项相互独立的事实：

- **依据** —— 这条路线在这类设备上有多充分的文档说明它能工作，即调研给出的等级：A（厂商有文档）、B（可复现
  的社区结果）、E（只有通用后端有文档）和 U（什么也没找到）。
- **在此测试过** —— 本项目是否在这台设备所属类别的硬件上验证过这条路线。本应用运行的大多数设备，本项目都无
  法测试；它们的路线以**未验证支持**的形式发布，产品会用平实的话说明这一点。

路由器的规则，包括自动何时可以使用未测试的路线，见
[`algorithms/engine-routing.md`](../algorithms/engine-routing.md)。哪些类别已经测试过，见
[`local-asr-support-matrix.md`](../local-asr-support-matrix.md)。

## 本设备上的检查

每条路线，无论测试过与否，都要在它的第一个任务之前在本设备上通过一次**本机检查**：一段内容已知的短片段，经
这条路线转写，与那些词比较，并计时。结果按一个六段式的键存档 —— 适配器版本、模型文件的哈希、操作系统版本、
驱动版本、处理器和精度 —— 因此其中任何一项更新都会要求重新检查。检查失败的路线在这里不会被使用，原因会保留
给诊断页面。

检查用的片段随第一个真正的引擎（L1）一起发布。在那之前，未经检查的路线会不经检查地运行 —— 而在没有编译进任
何引擎的情况下，这永远不会发生。

## 应用在路线中途停掉时

每次原生调用之前 —— 加载模型、运行一个窗口、一次检查 —— 应用都会写下一个指明路线的**进行中标记**，并在调用
返回时清除它，无论成功、失败还是被取消。下次启动时发现的标记，意味着进程死在了那条路线里。该路线在本设备上
被记为 `crashed`，在那个键下再也不会被自动选中。被打断的任务按回退策略继续，路线的改变连同原因
`ROUTE_CRASHED` 一起写进任务，因此一次崩溃只损失一个窗口，绝不会陷入崩溃循环。

## 回退策略

任务要求的路线无法运行时，由设备本地的回退策略决定接下来怎样：

| 策略 | 结果 |
|---|---|
| `sameModelOnCpu`（默认） | 同一模型在 CPU 上运行。 |
| `none` | 任务失败，并说明原因。 |
| `systemRecognizer` | 操作系统自带的系统语音识别（后续里程碑），一个不同的引擎，并如实标明。 |

回退是一个可见的事件，绝不是替换：任务记录它要求的是什么、实际运行的是什么、从哪个窗口开始，以及原因。只有
路线问题 —— 驱动缺失、设备丢失、加速器内存不足、崩溃 —— 才能由 CPU 来接手；损坏的模型或不支持的语言在哪里
都会同样失败，所以任务直接失败。

## 任务记录些什么

本地任务把 `local` 记为来源，把本地模型的 id 记为模型。在通常的字段之外，它还保存：

- `options.device` —— 用户要求在哪里运行：`auto`（缺省）、`cpu` 或一个路线键；
- `route` —— 要求的是什么，以及开始时选定的路线，连同它的依据等级和是否已在此类设备上测试；
- `artifactRevision` —— 加载的模型包修订版；
- `chunks[].placement` 与 `chunks[].routeKey` —— 每个窗口实际在哪里运行，按运行时报告的来记（`cpu`、`gpu`、
  `npu`、`mixed` 或 `unknown` —— 绝不猜测）；
- `fallbacks` —— 每一次偏离所要求路线的改动。

方案指纹包含模型包修订版和所要求的设备，因此模型包更新或改要另一个处理器会丢弃缓存的窗口。回退不会改变它：
GPU 在回退之前完成的窗口出自同一个模型，会被保留。见 [`chunking-and-resume.md`](chunking-and-resume.md)。

本地任务新增的失败类型是 `modelNotInstalled`、`modelDamaged`、`unsupportedByModel`、`engineUnavailable`、
`outOfMemory` 和 `routeCrashed`，每一种都附上引擎自己的原话。

## "未验证"对用户意味着什么

本项目没有在这类设备上测试过的路线，在任何展示路线的地方都会如此标明。它已经构建并由测试覆盖，在它的第一个
任务之前在本设备上通过了检查，并且只在 [`engine-routing.md`](../algorithms/engine-routing.md) 允许时才被自
动使用；实验性的路线只在用户选择时运行。如果它在一段长录音上表现异常，进行中标记、回退策略和逐窗口的记录会
把损失限制在一个窗口之内。诊断页面（L1）会复制一份诊断报告，包含设备、路线、它的检查和速度 —— 不含文件名，
也不含文本 —— 用户可以手动发送；应用不会把它发送到任何地方。
