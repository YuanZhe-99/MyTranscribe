# WebDAV 同步

在用户配置之前同步是关闭的，配置之后它也只与用户填写的那台服务器通信。它携带的是**配置** —— 来源、模型
与默认值 —— 以及在端点安全时携带其 API Key。录音和转写稿从不同步。

引擎本身位于共享的 `myapps_data` 包中，文档在 `packages/myapps_data/doc/en-us/`。本页说明它在这里是如何
配置的。

## 注册了什么

一个数据模块：

| 字段 | 取值 |
|---|---|
| 文件 | `transcribe_settings.json` |
| 模块 id | `settings` |
| 远端路径 | `/MyTranscribe` |

`lib/app/data_modules.dart` 是这些名称唯一出现的地方。若将来有第二个模块，只能追加到注册表末尾，绝不能插
在这一条之前 —— 引擎把注册表顺序视为有意义的。

## 一次同步的过程

1. 取得远端 `.lock`，使两台设备不会同时上传。
2. 下载远端的设置文件。
3. 若它不存在，就把本地这份作为新文件上传。若两边的原始字符串完全相同，保存基线快照并结束 —— 这是快路径，
   也正是该文件的格式必须与存储中枢写出的一致的原因。
4. 否则做三路合并：本地、远端，以及上次达成一致时的基线快照。
5. 把合并结果写到本地、上传、保存新的基线快照、释放锁。

`.sync_base/` 中的基线快照是删除得以传播而不是复活的原因：出现在基线中而本地没有的记录，是在这里被删掉
的，而不是在那边新增的。

## 合并

`lib/shared/services/sync_merge.dart` 封装共享的 `mergeRecords` 引擎。记录以 id 为键，按 `modifiedAt`
比较。

- 只有一边改动 → 那一边胜出。
- 两边都没改 → 保持本地不变。
- 某一边新增了记录 → 保留。
- 一边删除、另一边未动 → 删除传播。
- 一边删除、另一边编辑 → 编辑胜出；有意的改动胜过一个空缺。
- 两边都改了 → **冲突**，除非内容相同。

"内容相同"比较的是记录的 `id`、`kind` 与 `payload` —— **不是**时间戳。两台设备相隔一分钟把同一个来源改成
同样的名字，并没有在任何事情上产生分歧，让用户在两份一模一样的配置之间做选择只是噪音。

冲突**绝不**自动解决。所有调用点的 `autoResolve` 都是 false。每条冲突记录都会给用户一个对话框，显示两个
版本及其时间；关闭其中任何一个都会中止整轮解决：什么都不上传，冲突保持待处理，也不会悄悄保留某条记录。用
户确实回答了的冲突，会在重新取得锁之后定案。

无论哪个版本胜出，它都会吸收另一边的未知字段，因此在冲突中落败绝不会删掉新版本写入的字段。

## 强制上传与强制下载

两者都跳过合并。强制上传用本地文件替换远端，丢失上次同步以来的远端改动；强制下载则相反。两者都在与普通同
步相同的锁和同一个进行中保护下运行，并且都有一个确认对话框，说明哪一边会丢失。

## 自动同步

`AutoSyncService` 封装共享的调度器。它的触发点是固定的：启动时一次、恢复前台时一次、每 15 分钟一次，以及
最后一次本地保存后 30 秒（后沿防抖，因此一连串编辑只花一次同步）。重叠的触发由进行中保护丢弃。后台发现的
冲突**不**在后台解决 —— 状态变为"有待处理的冲突"，等用户打开同步页面。

## API Key

密钥不属于该模块，因此不随它一起传输。它们单独交换，且仅在端点安全时进行。该交换在 WebDAV 外观层里、引擎
返回之后立刻运行，使用同一台服务器与同一个远端目录，用条件式 PUT 而不是引擎的锁 —— 密钥文件是按键"后写者
胜"的映射，没有基线快照也没有合并状态，因此并发写入的结果是一个被拒绝的请求加一次重新合并，而不是一次丢失
的更新。把它放进上锁的时间窗内，就意味着为了没有增加的安全性去改动四个应用共用的引擎。

关于什么算安全、以及会如何告知用户，见
[`features/secure-secrets-sync.md`](features/secure-secrets-sync.md)。

## 凭据

WebDAV 服务器地址、用户名和密码以明文存放在 `webdav_config.json`，与兄弟应用一致。隐私政策中已写明这一
点。该文件从不同步、不备份、不导出。
